# 96 孔板浓度梯度配液规划

打开页面即可配置本次板实验（无介绍页）。前端的**板位图、逐孔清单、移液步骤、用量汇总全部取自服务端同一次计算结果**——不存在“计算表改了、孔位图还是旧版”的第二份事实。

## 要解决的问题

- 母液浓度 / 目标浓度序列 / 重复数 / 每孔终体积（含 µL、mL、pM…M 单位）在服务端统一换算与计算。
- 排布**之前**就看到能否装进一块 96 孔板。
- 直接加母液无法可靠配出（剂量或孔内补齐量低于移液器最小体积）时，给出**中间稀释链**：每次母液分装、中间液分装、配制稀释液、给孔加样的体积都必须 ≥ 移液器最小可操作体积；必要时显式**超配**并把超配计入真实用量，绝不把亚最小体积四舍五入成 0。
- 母液是**有限资源**：母液需备 > 可用量时，状态明确为「不能执行」并给出原因，不会同时出现「可执行」总览。
- 调整重复数 / 对照孔 / 删除组之后，引用旧版本的孔位安排会被服务端拒绝（回退自动排布、清空旧选中），孔位与操作清单一起更新。
- 配液前确认一次：确认后的板位 + 操作清单成为**冻结快照**，之后修改草稿不会改写它；可导出 TXT / 逐孔 CSV / JSON。重新打开页面可找回确认方案逐孔核对。

## 运行

要求 Node 20+。

```bash
npm install
npm run dev        # 同时启动 API(4000) 与 Vite(5173)，打开 http://localhost:5173
```

生产模式（单进程，服务端托管前端构建产物）：

```bash
npm run build
npm start          # http://localhost:4000
```

环境变量：`PORT`（默认 4000）、`PLATE_DATA_FILE`（状态落盘路径，默认 `server/data/planner-state.json`）。

## 结构

```
shared/   前后端共享的领域类型与单位格式化（内部规范单位：浓度 nM，体积 µL）
server/   Express API + 计算引擎（计算只发生在这里）
  src/normalize.ts  输入规范化与硬校验（单位一次性换算）
  src/chain.ts      每单元的直接加样 / 中间稀释链构造（守恒 + 移液器约束 + 超配）
  src/assign.ts     96 孔排布、展开、孔位安排校验（拒绝引用旧组/旧序号/数量不符）
  src/compute.ts    统一总装：孔清单、移液步骤、用量汇总、守恒核对、可执行性
  src/store.ts      纯 reducer：草稿可改，确认即冻结（方案修订测试直接针对它）
  src/exporter.ts   TXT / CSV 导出（含计算依据与孔位身份）
  src/persist.ts    JSON 落盘（重开页面找回方案）
web/      React + Vite：配置面板 / 8×12 板位 / 孔详情 / 配液步骤 / 确认与导出
```

## 关键规则

- 每孔：`加样体积 + 孔内稀释液补齐 = 终体积`，`目标浓度 × 终体积 = 加样液体浓度 × 加样体积`。
- 中间液节点：`上游取液 + 稀释液 = 配制总量`，`上游浓度 × 取液 = 本节点浓度 × 配制总量`；配制总量 = 下游消耗 + 操作损耗（必要时再加超配）。
- 同组同浓度点的重复孔共享一份中间液，损耗只在配制处计一次；步骤里列出该液体服务的全部孔位，点孔位可反查涉及步骤。
- 一个孔只有一份处理定义；空孔就是空孔，不接受处理也不进入操作清单。
