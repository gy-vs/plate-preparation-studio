# 96 孔板浓度梯度配液规划器

打开页面即可配置本次板实验（没有介绍页）：输入母液浓度/可用量、目标浓度序列、重复数、
每孔终体积与移液器量程后，**板位图与操作清单都来自服务端同一份计算结果**——
改了浓度或板位，孔位、用量、步骤同步改变，不会再出现“计算表已改、孔位图还是上一次”的情况。

## 它保证什么

- **单位不混用**：内部统一按 µL 运算，输入 mL 一律 ×1000；所有界面与导出都显式带单位。
- **母液不是无限的**：每组必须填实际可用量；用量超限直接判不可执行，总览不会同时又给出“可执行”。
- **移液器最小体积约束**：目标浓度对应的母液量低于最小可操作体积时，不做“四舍五入成零”，
  而是搜索整数倍**中间稀释**；中间液配方、aliquot、稀释液、批次（含主动多配以保证 aliquot 可取）
  与额外母液消耗都会明确列出。批次大到无法现实配制时判无解并说明原因。
- **装板检查在排布之前**：总孔数 > 96 直接阻断。
- **一个孔只有一份定义**：调整重复数/目标数/对照数后，旧排布立即失效并报错；空孔始终是空孔。
- **改板位即改清单**：手工移动孔位后，该孔出现在对应配液步骤的孔列表中（可按孔查步骤，也可按步骤查孔）。
- **操作损耗计入准备量**：每个稀释液/中间液分装批次固定多备损耗量，准备量向上取整 0.1 µL。
- **确认即锁定**：确认时服务端用同一引擎重算校验（前端无法伪造“可执行”）；
  已确认方案只写一次，之后改草稿不会改写它；存档带 sha256 指纹，被改动的方案自动隔离（409），不被静默展示。
- **导出含计算依据与孔位身份**：单文件 HTML（板位图、逐孔加液、按序步骤、用量汇总、指纹），可直接发同事。

## 目录结构

```
shared/            前后端唯一共享：96 孔板几何、API 契约与类型
server/src/core/   计算规则（只在服务端执行）：
  units.ts           µL 归一化、取整、比较容差
  dilution.ts        C1V1=C2V2；直接法/整数倍中间稀释求解（含移液器与批次可配制约束）
  validate.ts        输入校验与单位归一化
  assignment.ts      自动排布与手工排布严格校验
  engine.ts          唯一计算入口：孔位、加液、步骤、汇总、计算依据（同一份事实）
  store.ts           已确认方案不可变存储 + sha256 完整性隔离
server/test/       体积守恒 / 移液器约束 / 排布一致性 / 方案修订 / HTTP 集成测试
web/src/           React 界面：配置、96 孔板、按孔/按步骤视图、汇总、确认与找回
```

## 运行

```bash
npm install

# 开发：后端 :3001，前端 :5173（/api 自动代理到后端）
npm run dev

# 生产：构建前端 + 编译后端，单进程托管
npm run build
npm start            # http://localhost:3001

# 测试（23 项：体积守恒、移液器约束、排布一致性、方案修订、HTTP 集成）
npm test
npm run typecheck
```

环境变量：`PORT`（默认 3001）、`DATA_DIR`（默认 `server/data`，存放已确认方案 JSON）。

## 计算模型摘要

- 直接法：每孔母液 `s = C目标/C母液 × V终`，稀释液 `V终 − s`；二者均须落在移液器 `[min, max]` 内。
- 中间稀释：整数倍数 D，中间液浓度 `C母液/D`；批量
  `batch = ceil_0.1(max(n·m + 损耗, min·D))`（第二项把母液 aliquot 抬到 ≥ 最小可操作体积），
  `aliquot = batch/D`、稀释液 = `batch − aliquot`；批次超过移液器量程 10 倍视为不现实配制。
- 母液用量：直接法为 `Σ 每孔量 × 孔数`；中间稀释为实际 aliquot（含损耗与主动多配）。
- 排布满 96 板才允许确认；确认后内容以 sha256 指纹封存，后续草稿修改只产生新计算，不动旧快照。
